# Study Method — GCP Data Engineering Certifications (PDE + ACE)

## 1. Objective

This document defines the study methodology used to prepare for:
- Google Cloud Professional Data Engineer (PDE)
- Google Cloud Associate Cloud Engineer (ACE)

The focus is on:
- long-term retention
- practical application
- clear documentation
- bilingual reinforcement (PT → EN)

---

## 2. Core Principles

- Learn in layers (study → apply → review)
- Delay application to force recall
- Write before reviewing
- Prefer active recall over passive review
- Use Git as the single source of truth

---

## 3. Daily Learning Cycle (Weekdays)

### Morning — Study (Input)
**Goal:** Acquire new knowledge

Activities:
- Watch course lessons
- Read official documentation
- Take short handwritten or digital notes

Rules:
- No Git implementation in the morning
- No over-documentation
- Focus on understanding concepts

---

### Afternoon — Apply (Output)
**Goal:** Convert knowledge into practice

Activities:
- Implement concepts in GCP
- Create scripts, configs, or examples
- Replicate *previous day's* content whenever possible

Rules:
- Expect implementation to take longer than study
- Break when blocked, but document blockers
- Code > notes

---

### Night — Review & Documentation (Consolidation)
**Goal:** Strengthen memory and understanding

Activities:
- Write daily README (PT)
- Answer what was learned, what failed, and why
- Summarize without rewatching content

Rules:
- README is always the last task of the day
- Write from memory first, then validate

---

## 4. English Reinforcement Strategy

English is trained daily through:
- Rewriting previous day README in English
- Translating concepts manually (no auto-translation)
- Prioritizing clarity over perfect grammar

Rule:
- Writing > reading > translating

---

## 5. README Daily Structure (Reference)

Each daily README must answer:

- Objective of the day
- What was done
- How it was done
- What worked
- What did not work
- Why decisions were made
- What would be done differently
- Key learnings
- Open questions

---

## 6. Weekly Reinforcement (Weekend)

### Review
- Read all READMEs from the week
- Identify weak points and patterns

### Quiz
- Open-ended questions only
- Written answers (no multiple choice)
- Based on weekly READMEs

Goal:
- Force recall
- Identify gaps
- Strengthen reasoning

---

## 7. Tooling

- Git: version control and learning log
- GCP Console & CLI: practice environment
- Markdown: documentation standard
- No task managers required beyond Git

---

## 8. Adjustment Rule

This method is iterative.

If fatigue, overload, or stagnation occurs:
- Adjust duration, not consistency
- Reduce scope, not frequency
- Never skip documentation entirely

---

## 9. Definition of Progress

Progress is measured by:
- Ability to explain concepts without notes
- Quality of READMEs
- Reduction of implementation friction
- Quiz performance

Not by:
- Hours watched
- Videos completed
