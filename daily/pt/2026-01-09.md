# Diário de Estudo — Dia 1

## Projeto
GCP Data Engineering Portfolio — Crypto Data Pipeline

## Objetivo do dia
Criar toda a base do projeto:
- identidade profissional
- repositório Git
- ambiente GCP
- arquitetura de Data Lake
- ingestão inicial de dados via API

## O que eu fiz
- Criei e-mail profissional e contas no GitHub e GCP
- Estruturei o repositório Git com pastas e padrões definidos
- Configurei o projeto no GCP via Cloud Console e Cloud Shell
- Ativei APIs essenciais e configurei billing com alerta
- Criei o bucket no GCS e defini as camadas (raw, processed, curated)
- Escolhi a fonte de dados (CryptoCompare)
- Desenvolvi dois scripts de ingestão via API:
  - preços globais do Bitcoin
  - volume negociado por exchange
- Baixei aproximadamente 4 anos de dados históricos
- Subi os dados para o bucket na camada raw
- Criei external tables no BigQuery
- Defini a arquitetura entre raw, processed e curated

## Como eu fiz
- Utilizando Git Bash e Cloud Shell
- Usando Python para integração com APIs REST
- Usando gsutil para upload de dados
- Usando bq CLI para criação de datasets e external tables
- Seguindo princípios de Data Lake e Data Engineering

## O que funcionou
- Estruturação do projeto desde o início
- Organização dos dados por asset, pair, exchange, ano e mês
- Uso de external tables para leitura direta do GCS
- Separação clara de responsabilidades por camada

## O que não funcionou
- Tentativas de uso de wildcards recursivos (`**`) no BigQuery
- Tentativa inicial de misturar metadados (asset/pair) na camada raw

## Por que fiz assim
- Para seguir padrões profissionais de engenharia de dados
- Para facilitar reprocessamento, escalabilidade e manutenção
- Para construir um projeto defensável em entrevistas técnicas

## O que eu mudaria
- Automatizar a criação das external tables via script
- Criar validações automáticas após ingestão dos dados

## O que eu aprendi
- Limitações reais do BigQuery com external tables
- Importância de modelar bem a camada raw
- Diferença clara entre processed e curated
- Como decisões simples impactam escalabilidade

## Observações
- O setup inicial é trabalhoso, mas economiza muito tempo depois
- Esse tipo de base é essencial para projetos reais de dados
