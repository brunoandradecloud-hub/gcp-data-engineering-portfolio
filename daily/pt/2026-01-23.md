## 📚 O que eu estudei hoje

### 🧱 Cloud Data Fusion (Visual ETL)

* **Pipeline Studio:** Interface visual para criação de DAGs complexas sem necessidade de código (No-code/Low-code).
* **Wrangler:** Preparação interativa de dados através de **Recipes** e diretivas (ex: `drop :body`), permitindo feedback em tempo real.
* **Arquitetura efêmera:** Compreensão de que o Data Fusion apenas orquestra, enquanto o processamento real ocorre em clusters **Dataproc** ou **Dataflow**.

### 🎼 Orquestração de Pipelines

* **Cloud Composer (Airflow):** Uso de DAGs para gerenciar dependências complexas e o uso estratégico de **Provider-specific Operators** (ex: `DataprocSubmitJobOperator`) em vez de Bash.
* **Cloud Workflows:** Alternativa serverless de baixo custo para encadeamento simples de APIs via YAML/JSON.

### 📊 Observabilidade e SRE de Dados

* **Cloud Logging vs. Monitoring:** Separação entre análise de causa raiz (logs passados) e alertas proativos (métricas presentes).
* **Structured Logging:** Importância do formato JSON para criação de **Log-based Metrics**.
* **Segurança (IAM):** Diferenciação entre `Logging Viewer` e `Private Logs Viewer` para proteção de PII.

## 🛠️ O que eu fiz (Troubleshooting Prático)

Hoje o foco foi entender os detalhes operacionais que definem o sucesso de um pipeline visual:

1. **Validação de Ingestão CSV:** Notei que o parser de CSV no Data Fusion consome a primeira linha para o cabeçalho, alterando a contagem de registros (ex: 893 na origem → 892 no destino), ponto crucial para auditoria.
2. **Configuração de Provisionamento:** Entendi o tempo de latência (15-20 min) para a criação dos recursos computacionais disparados pelo Data Fusion.
3. **Implementação de DLQ Visual:** Configurei a separação de registros válidos e inválidos usando portas de erro nos nós do Data Fusion.

## ⚠️ Pontos de Atenção (Armadilhas de Prova)

* **A Falácia do Processamento:** A prova pode sugerir que o Data Fusion processa dados; a resposta correta é que ele **delega** para Dataproc/Dataflow.
* **IAM do Data Fusion:** Requer permissões específicas de `Service Account User` e `Dataproc Administrator` para funcionar corretamente.
* **Alertas Proativos:** Se o cenário pede detecção de falha imediata, a resposta é **Cloud Monitoring**, não apenas Logging.
